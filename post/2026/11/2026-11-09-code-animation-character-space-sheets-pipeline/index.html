왜 동영상 생성 AI 대신 코드인가

영상은 힉스필드·Seedance 같은 클라우드 동영상 AI를 쓰면 부드럽고 화려한 장면을 얻을 수 있지만, 1분 분량을 만들 때 비용이 커지고 마음에 들지 않으면 다시 생성해야 한다고 설명한다. 제작자가 말하는 코드 방식의 장점은 몇 초에 어떤 효과가 일어날지 수치로 지정할 수 있다는 점이다. 반대로 현실적인 사람의 움직임이나 자연스러운 물리 표현은 코드만으로 어색해질 수 있다. 이는 영상 제작자의 경험에 기반한 비교이지, 모든 모델·모든 장면의 비용과 품질을 측정한 벤치마크는 아니다. 영상 00:28, 영상 01:09

첫 시도에서 드러난 이미지와 관절의 문제

초기에는 HTML로 이미지를 만들고, 로컬 사진에서 인물을 잘라 조각 인형처럼 움직이게 했다. 그러나 누끼 경계와 관절 분리 때문에 팔을 들 때 겨드랑이 주변이 무너지고, 통그림을 써도 어깨·팔이 목각 인형처럼 보였다고 설명한다. 고양이 이미지도 점프하는 순간 형태가 기괴하게 변했다. 이 실패는 코드가 나쁘다는 뜻보다, 한 장의 정지 이미지를 여러 자세로 재사용하려면 관절·가림·깊이 정보를 별도로 설계해야 한다는 신호다. 영상 02:02, 영상 03:01

코드의 강점은 물체 간 규칙을 고정하는 데 있다

고양이가 밥그릇에 머리를 파묻는 초기 장면에서 제작자는 물리적으로 이상한 접촉을 발견한다. 동영상 AI라면 프롬프트를 고쳐 다시 생성하는 방식이지만, 코드 애니메이션에서는 “고양이 머리와 그릇이 닿지 않게 한다”는 제약을 명시할 수 있다. 영상은 수정 후 물체가 겹치지 않는 장면을 코드의 장점으로 보여준다. 영상 04:42, 영상 05:18

  3. 자연어 요구를 테스트 규칙으로 바꾼다. “어색하지 않게” 대신 “머리와 그릇이 겹치지 않음”, “벽지 색이 장면 사이에 변하지 않음”처럼 판정 가능한 조건으로 적는다. 영상 05:18, 영상 08:04
  4. 도구마다 책임을 나눈다. 이미지 생성, 코드, 음성, 편집, 검수의 입력·출력을 문서화하고 한 도구가 전체 파이프라인을 책임진다고 가정하지 않는다. 영상 11:06
  5. 가설-검증 주기를 운영한다. 조회수가 낮다고 즉시 실패로 결론 내리지 말고, 어떤 가설을 몇 편 테스트했는지 기록한 뒤 채택·기각한다. 영상 10:40
  6. 자산을 데이터베이스에 보관한다. 이미지, 시트, 코드, 프롬프트, 검수 기록을 버전과 권한 정보와 함께 저장해 다음 에피소드에서 재사용한다. 영상 11:48

핵심 요약

  • 코드 애니메이션은 실사 동작을 완벽히 대체하는 방법이 아니라, 시간·도형·충돌·UI를 명시적으로 통제하는 제작 방식이다. 영상 01:09
  • 단일 이미지의 관절 왜곡을 줄이려면 여러 컷 이미지와 인물 시트를 준비하고, 장기 영상에서는 공간 시트와 페르소나까지 고정해야 한다. 영상 03:15, 영상 07:55
  • Claude Code는 이미지 자산을 만드는 도구라기보다 자산을 장면·규칙·검수 흐름으로 조립하는 에이전트로 활용된다. 영상 11:06
  • 지속 가능한 제작의 핵심은 한 번의 생성이 아니라 실패와 가설, 승인된 자산을 데이터베이스에 축적하는 것이다. 영상 12:29

결론

동영상 AI 없이 가족 애니메이션을 만든다는 말은 AI를 쓰지 않는다는 뜻이 아니다. 이미지 생성, 코드 에이전트, 음성·음악·편집 도구를 각각의 강점에 맞게 조합하고, 사람이 일관성 규칙과 검수 기준을 설계한다는 뜻이다. 짧은 장면의 성공보다 중요한 것은 캐릭터·공간·페르소나·실패 기록을 재사용 가능한 자산으로 바꾸는 일이다. 그렇게 해야 다음 에피소드가 매번 처음부터 시작되지 않는다.
