Claude Code 하나만 단독으로 사용할 때는 터미널 창 하나로도 충분합니다. 하지만 Codex, OpenCode, Kimi, Cursor 등 다양한 AI 코딩 에이전트를 함께 띄워 병렬로 개발을 진행하기 시작하면, 터미널 창이 금세 8개 이상으로 불어나며 작업 혼선이 발생합니다.

단순히 창이 많아지는 문제보다 더 심각한 것은, **"현재 어떤 에이전트가 코드를 작성 중이고, 어떤 에이전트가 사용자의 명령 승인(Human Gate)을 기다리며 멈춰 있는지"**를 한눈에 파악하기 어렵다는 점입니다.

**herdr**(`https://herdr.dev`)는 이러한 AI 에이전트 동시 운용 환경을 위해 태생부터 설계된 **오픈소스 무료 터미널 멀티플렉서(Terminal Multiplexer)**로, 전통적인 tmux와 cmux를 대체하는 에이전트 전용 작업 공간을 제공합니다.

## 1. herdr가 해결하는 핵심 과제

1. **에이전트 상태 실시간 자동 감지**: 실행 중인 에이전트 프로세스를 감지하여 작업 진행 중인지, 사용자 입력을 기다리는 중인지 시각적으로 분류합니다.
2. **세션 지속성 (Persistence)**: 터미널 클라이언트 창을 닫아도 백그라운드 서버 프로세스에서 에이전트가 작업을 계속 이어갑니다.
3. **직관적인 GUI 및 스페이스 분할**: 마우스 클릭과 단축키를 통해 창 분할, 탭 전환, 스페이스 관리를 손쉽게 조작합니다.
4. **에이전트-터미널 상호작용 (Agent Skill)**: 에이전트가 직접 herdr의 페인을 제어하고 다른 에이전트의 출력을 참조할 수 있는 스킬 인터페이스를 제공합니다.

## 2. 주요 구조 및 핵심 기능

### Agents 사이드바 & 상태 대시보드
화면 좌측에 상시 고정되는 **Agents 사이드바**는 현재 활성화된 에이전트들을 나열하고 상태를 표시합니다:
* **Working**: 백그라운드에서 추론 및 도구 호출 수행 중
* **Waiting for Input / Gate**: 사람의 확인(승인)이나 프롬프트 입력을 기다리는 상태
* **Idle / Completed**: 작업 완료

사용자는 창을 일일이 열어보지 않고도 사이드바의 색상과 상태 배지만 보고 즉각적인 개입이 필요한 에이전트로 바로 전환할 수 있습니다.

### 클라이언트-서버 구조 기반 세션 영속성
로컬 터미널 앱을 종료하거나 맥북을 닫아도 백그라운드 서버 데몬이 세션을 유지합니다. 원격 VPS 환경에서도 백그라운드로 장시간 에이전트 팀을 운용하기에 매우 유리합니다.

### 플러그인 마켓플레이스 및 헤드리스 관찰
헤드리스(Headless) 모드로 백그라운드에서 실행되는 에이전트 작업을 실시간으로 시각화하고, Claude Code가 작성한 코드를 Codex가 교차 검토하는 협업 과정을 라이브로 모니터링할 수 있습니다.

## 3. 기존 도구들과의 비교 분석

### vs tmux / cmux
* **tmux**: 전통적인 엔지니어가 키보드 단축키로 터미널을 수동 분할하는 범용 도구입니다. 에이전트의 내부 상태(승인 대기, 툴 호출 등)를 인식하지 못합니다.
* **herdr**: AI 에이전트 프로세스 자동 감지, 상태 배지, 에이전트 제어용 전용 스킬(Agent Skill)이 기본 내장되어 있어 에이전트 오케스트레이션에 최적화되어 있습니다.

### vs Orca
* **Orca**: Git Worktree 기반의 물리적 디렉토리 격리와 브랜치 충돌 방지에 집중합니다.
* **herdr**: 여러 에이전트의 터미널 실행 세션 관리 및 실시간 상태 모니터링에 집중합니다.

## 4. 간편 설치 가이드 (macOS / Linux)

```bash
# 한 줄 스크립트 설치
curl -fsSL https://herdr.dev/install.sh | sh

# herdr 시작
herdr
```

다중 에이전트를 활용해 복잡한 시스템을 병렬로 개발하는 개발자에게 필수적인 차세대 터미널 오케스트레이션 툴입니다.
